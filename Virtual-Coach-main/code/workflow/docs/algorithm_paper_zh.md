# **算法：形式化验证约束下的迭代式 RAG 引导工作流合成**

### **问题设定**

我们考虑一种工作流合成系统：每个原子能力被封装为一个**节点**（node），并以 JSON 规范描述（如类型、参数、输入/输出模式等）；完整工作流由多个节点及其连接关系组成，同样以 JSON 配置表示。给定用户的自然语言需求（以及可选的原始文件），系统目标是自动生成满足需求且符合预定义格式与节点约束的工作流 JSON。

记

* **\mathcal{K}=\{d_i\}** 为文档知识库（包含工作流定义、节点定义、动作定义以及实现说明等），
* **x** 为用户请求，由需求文本 **r** 与可选原始文件 **f** 构成，
* **W** 为候选工作流 JSON，
* **\mathrm{Verify}(W)\to(\texttt{ok},\mathcal{E})** 为形式化验证器，输出是否通过以及错误集合 **\mathcal{E}**。

我们的目标是输出验证通过的工作流 **W^\***，并同时产出一份可追踪的运行记录（log），用于复现与调试检索、规划与验证过程。

---

### **方法概述**

所提出的方法以迭代方式交替执行三类步骤：

1. 在当前已加载知识的条件下，由大模型**规划（planning）**生成候选工作流；
2. **对候选工作流进行** **形式化验证（formal verification）** **，检查格式与约束是否满足；**
3. 若候选工作流无效或不确定，则执行**定向检索（targeted retrieval）**，扩充必要的文档知识后继续迭代。

该设计使得：（i）借助验证器保证严格的格式与约束遵从；（ii）通过按需加载知识，提升检索效率并减少无关信息干扰。

---

### **模块组成**

**检索器**\mathrm{Retrieve}(\mathcal{K},q)**：对查询 **q** 返回 top-**k** 个相关文档片段（RAG）。**

**规划器**\mathrm{Plan}(r,f,\mathcal{C})**：基于当前上下文 **\mathcal{C}** 的大模型规划模块，生成候选工作流 **W** 及结构化的决策说明。**

**验证器**\mathrm{Verify}(W)**：两阶段检查：**

* **模式验证（schema check）**：例如 JSON Schema/Pydantic，验证字段结构、类型与枚举合法性；
* **规则验证（rule check）**：验证图结构拓扑、节点类型存在性、输入输出兼容、参数约束，以及（可选）与标准工作流模板的对齐约束。

**缺口分析器**\mathrm{Gap}(\mathcal{E})**：将验证错误 **\mathcal{E}** 映射为下一轮检索的意图/查询，用于获取缺失的约束与示例。**

---

### **算法描述**

**我们维护一个检索上下文集合 **\mathcal{C}** 与最大迭代轮数 **T**。**

1. **初始化（Level-0 基础知识）**
   加载工作流与节点的基础格式定义（例如 **workflow/base.md** 与 **node/base.md**），并加载可用节点/工作流类型的轻量索引或注册表，得到初始上下文 **\mathcal{C}_0**。
2. **迭代合成循环**（对 **t=1** 到 **T**）
   * **规划（Planning）**：在当前上下文下生成候选工作流：
     **(W_t,\pi_t,s_t)\leftarrow \mathrm{Plan}(r,f,\mathcal{C}_{t-1}),**
     其中 **\pi_t** 为结构化决策记录（例如选择了哪些节点及其理由），**s_t** 为可选的置信度/不确定性信号。
   * **形式化验证（Formal Verification）** **：**
     **(\texttt{ok}_t,\mathcal{E}_t)\leftarrow \mathrm{Verify}(W_t).**
     **若 **\texttt{ok}_t=\texttt{true}**，则输出 **W^\*=W_t** 并终止。**
   * **定向检索（Level-1 知识扩充）** **：**
     若验证失败（或置信度低于阈值），则根据错误 **\mathcal{E}_t** 生成下一轮所需的知识查询：
     **Q_t \leftarrow \mathrm{Gap}(\mathcal{E}_t,\pi_t),**
     并执行定向检索扩充上下文：
     **\Delta \mathcal{C}_t \leftarrow \mathrm{Retrieve}(\mathcal{K},Q_t),\quad
     \mathcal{C}_t \leftarrow \mathcal{C}_{t-1}\cup \Delta \mathcal{C}_t.**
     进入下一轮迭代。
3. **终止条件**
   若经过 **T** 轮迭代仍未得到验证通过的工作流，则返回当前最优候选（best-effort），并输出最终验证错误 **\mathcal{E}_{T}** 与停止原因（达到最大迭代次数）。
4. **人工校正与 Bug 注入（可选）**
   用户或外部验证器可给出校正意见或 Bug 报告 **\beta**。我们将其视为额外需求 **\Delta r**，更新 **r \leftarrow r \oplus \Delta r**，并从步骤 1 或步骤 2 重新执行合成循环（可复用已缓存的检索上下文）。

---

### **日志与可复现性**

系统在每轮迭代中记录：

* 输入需求与原始文件摘要；
* 检索的文档片段标识、分数与来源；
* 规划输出（候选工作流哈希、决策记录、置信度等）；
* 验证结果（schema 错误、规则违规项）；
* 下一轮的检索意图与查询。

该日志支持复现实验、定位失败模式，并可用于离线分析与系统改进。

### **伪代码**

```
算法1：RAG + 形式化验证的工作流合成
输入：需求 r，可选文件 f，知识库 K，最大迭代次数 T
输出：验证通过的工作流 W*（若存在）、决策记录 Π、运行日志 L

1: C ← LoadBaseKnowledge(K)            ▷ Level-0：基础工作流/节点规范
2: 初始化日志 L
3: for t = 1..T do
4:     (W, π, s) ← Plan(r, f, C)       ▷ 基于当前上下文的大模型规划
5:     Append(L, "PLAN", t, hash(W), π, s)
6:     (ok, E) ← Verify(W)             ▷ schema + 规则两阶段验证
7:     Append(L, "VERIFY", t, ok, E)
8:     if ok then
9:         return (W, π, L)
10:    Q ← Gap(E, π)                   ▷ 从错误推导缺失知识需求
11:    D ← Retrieve(K, Q)              ▷ 定向检索（Level-1 扩充）
12:    C ← C ∪ D
13:    Append(L, "RETRIEVE", t, Q, ids(D))
14: end for
15: return (BestEffort(W), π, L)       ▷ stop_reason = max_iter
```

---

### （可选）设计说明

* **职责分离**：规划模块具随机性，验证模块确定性强，从而提升整体可靠性。
* **定向检索**：按需扩充上下文，降低上下文长度与噪声，提高正确性与效率。
* **模板对齐验证**：当提供标准工作流时，可将“必备子结构”写入规则，进一步提升格式稳定性。
